# Maps components & pages — specs

Scope `maps` (enable with `ds.py init --scopes product,maps`; it needs no other scope). Components live in `components/<file>.html` (category **Maps**); full pages in `patterns/<file>.html` (category **Maps Pages**). Maps components compose product components (`button-primary`, `button-secondary`, `icon-button`, `combobox`, `address-entry`, `text-field`, `slider`, `tabs`, `popover`, `modal`, `badge`, `empty-state`, `skeleton`, `alert`, `toast`, `data-table`) by id; wrap them, never re-style them. The docs are provider-agnostic: MapLibre GL JS with OpenStreetMap data, Leaflet, Google Maps JavaScript API and Mapbox GL JS are all wrapped the same way (section 1, "Wrapping a provider").

## 1. Rules for every maps surface
Sources are named as rules, not numbers: WCAG 2.2 (2.1.1 keyboard, 2.5.7 dragging movements, 1.1.1 non-text content, 1.4.1 use of color, 1.4.11 non-text contrast, 2.5.8 target size, 4.1.3 status messages, 3.3.1 error identification), the browser Geolocation API permission UX (ask from a button, never on load), the attribution requirements of OpenStreetMap/MapLibre, Google Maps and Mapbox, ARIA APG (`combobox`, `dialog`), and the Permissions API.

- **A map is never the only way to get the information** (WCAG 1.1.1, 2.1.1). Every `map-container` ships a text alternative with all markers: a `ul` (or `data-table` for many attributes) of places with name, address, distance and status, placed in the DOM next to the map and reachable by a "Skip map, go to list" link. The list is not hidden from sighted users on desktop (`map-list-sync`); on mobile it is the "List" view. Every action available on a marker (select, open details, get directions) is available on the list row.
- **The map is a labelled region, not an application.** `map-container` is a `<section aria-label="Map of stores near Berlin">` (a labelled `section` is already a `region` landmark; do not add `role="region"`). Use `role="application"` never; it turns off screen-reader browse mode for the whole canvas.
- **Keyboard pan and zoom when focused** (WCAG 2.1.1). The canvas wrapper has `tabindex="0"` and a visible focus ring; arrow keys pan by 10 percent of the viewport (Shift: 25 percent), `+`/`=` and `-` zoom, Home resets to the initial view, and Esc leaves a drawing or pin-drop mode. The keys are listed in a "Map keyboard help" disclosure next to the controls and announced once through `aria-describedby` ("Arrow keys pan, plus and minus zoom"). Keys are handled only when the wrapper has focus, so Tab is never trapped: Tab moves to the controls, markers, then the next element.
- **Never hijack scroll** (WCAG 2.1.1). Wheel and one-finger touch scroll the page; zoom needs Ctrl/Cmd + wheel or a two-finger gesture, and one-finger pan on touch needs two fingers while the page can scroll. A visible hint ("Use Ctrl + scroll to zoom the map", "Use two fingers to move the map") appears for 2 s on the first blocked gesture, is `role="status"` text, and is also in the help disclosure. Providers expose this (MapLibre `cooperativeGestures`, Leaflet `scrollWheelZoom: false` plus a handler, Google `gestureHandling: "cooperative"`, Mapbox `cooperativeGestures`).
- **Dragging has a single-pointer alternative** (WCAG 2.5.7). Pan is available as four Pan buttons (up, down, left, right) plus Zoom in and Zoom out in `map-controls`, each with a stable accessible name and a 44 px target (24 px minimum, WCAG 2.5.8). Drawing a pin or an area by drag has a non-drag path (click or Enter to place, numeric fields, `area-selector` radius slider).
- **Attribution is always visible** (OpenStreetMap, MapLibre, Google and Mapbox terms). Provider and data-source attribution ("© OpenStreetMap contributors", the Google logo, "© Mapbox") stays on screen at all zoom levels, in every state including `state:static-fallback` and the print or fullscreen view, with enough contrast to read (the wrapper adds a `color.bg.surface` backing). It is real text and links, never hidden, cropped, covered by a marker or control, or collapsed into an info button that starts closed unless the provider's terms allow it. Removing or restyling it is a licensing issue, not a design choice.
- **What the system can't guarantee inside a third-party canvas.** Tiles, labels, road names, basemap colors, the provider's own controls, built-in popups, Street View and the vector or raster canvas itself are drawn by the provider, so their contrast, text size, language, high-contrast mode, forced-colors, zoom/reflow behavior and screen-reader support are not under this system's control and are not covered by its WCAG claims. What the system does guarantee: everything it renders as DOM above or beside the canvas (`map-marker`, `marker-cluster`, `map-popup`, `map-controls`, the list, search, attribution wrapper, hints and status) meets the rules here. The `map-container` docs page states this plainly, and teams must pick a provider style whose labels have enough contrast against the pins (pins carry a `color.bg.surface` outline for that reason).
- **Markers and clusters are DOM buttons, not canvas shapes.** Use provider HTML markers (MapLibre `Marker` with an element, Leaflet `divIcon`, Google `AdvancedMarkerElement` with content, Mapbox `Marker`) so each is a real `<button>`. Do not rely on canvas-drawn symbols or the provider's default marker image for meaning; a canvas layer is allowed only when the same markers also exist in the list alternative and the docs say so. Above roughly 100 markers use `marker-cluster` and keep only the visible ones as DOM nodes; the list still holds all of them.
- **State is never color alone** (WCAG 1.4.1). Pins differ by shape and label as well as `color.map.pin.default|selected|visited`: selected is larger with a ring and a check glyph and `aria-pressed="true"`, visited has a check mark glyph and "Visited" in the accessible name, default is a plain circle with the place label or glyph. Routes differ by line style (solid driving, dashed walking, dotted transit) and a text legend, not only `color.map.route`.
- **Location is requested only from a button press** (Geolocation API permission UX). Never call `navigator.geolocation` on load or on map focus. The Locate button and the location picker's "Use my location" explain the benefit, then call it; show `state:locating` with text, and a timeout. A denied permission is a normal state with plain-language recovery and a manual path (section `location-picker`). Precise position is not stored without consent and is never sent to the provider unless the feature needs it.
- **Moving the map must not surprise** (WCAG 3.2.2 on input, 2.2.2 pause stop hide). Searching as the map moves (`map-search-page` `variant:search-as-move`) is a checkbox the user can turn off ("Search as I move the map"), results update after the move ends (debounced), focus is never moved, and the update is one polite `role="status"` message ("12 places in this area"). Animated fly-to and zoom (flyTo, easeTo) are instant jumps under `prefers-reduced-motion`.
- **Loading and errors are text.** `state:loading` is a `skeleton` with "Loading map" status; `state:error` is an `alert` with the reason ("Map couldn't load", "Map key invalid", "You're offline") and a Retry `button-secondary`; the list alternative still works. `state:static-fallback` shows a static image (provider static API or a prebuilt image) with an `alt`, the list, an "Open in Maps" link and the attribution, for no-JS, blocked tiles or data-saver.
- **RTL and units.** Logical properties for controls (`inset-inline-end`); controls keep their position semantics but mirror in RTL, map content is not mirrored. Distances use the user's locale and unit (km/mi) with the unit written; coordinates are never the only address.
- **Tokens**: `color.map.pin.default|selected|visited` (pin background), `color.map.pin.fg` (label or glyph on every pin; an addition so every fg is explicit), `color.map.route`, `color.map.cluster.bg|fg`. Contrast pairs: `pin.fg` on each pin at 4.5, each pin on `color.bg.surface` at 3, `route` on `color.bg.surface` at 3, `cluster.fg` on `cluster.bg` at 4.5, `cluster.bg` on `color.bg.surface` at 3. The template ships a dark theme only (`themes/dark.json`) because provider tiles are themed by the provider; light values pass on the high-contrast surface, so high-contrast inherits them. Pair-checks cover only DOM overlays, not the tile beneath.
- **Wrapping a provider.** Create the provider map in a div inside `map-container`; set the provider's own attribution control on; put `map-controls`, markers, clusters and popups as DOM siblings or provider HTML overlays; disable the provider's default controls and popups when replaced; set the provider's language and unit options from `lang`; and keep one source of truth for places (an array) that feeds both the markers and the list.
- **vs.**: `map-popup` vs `popover`: a popup is anchored to a marker and its place, follows pan and zoom, and returns focus to the marker; `popover` is for generic controls. `map-popup` vs `hover-card`: a popup never opens on hover alone (hover has no touch or keyboard equivalent); selecting a marker opens it. `location-search` vs `combobox`: `location-search` is a `combobox` specialised with place suggestions and map recentering; use plain `combobox` for non-geographic options. `location-search` vs `address-entry`: `address-entry` collects a structured postal address in a form; `location-search` finds a place to show on the map and may hand off to `address-entry` as the manual fallback.

## 2. Map surface

### map-container
- Markup: `<section aria-label="Map of stores near Berlin" aria-describedby="map-help">` holding a skip link ("Skip map, go to list"), the focusable canvas wrapper (`tabindex="0"`, visible focus ring), `map-controls`, the provider canvas, an attribution `<p>`/`<small>` and a help disclosure. The list alternative (`ul` of places) follows or sits beside it with the same data and an `h2`.
- Keyboard: when the wrapper is focused, arrows pan, `+`/`-` zoom, Home resets, Esc cancels a mode; Tab leaves. Pan buttons and zoom buttons are in `map-controls` as the WCAG 2.5.7 dragging alternative.
- No scroll hijack: Ctrl/Cmd + wheel or two fingers zoom and move; the hint text is visible and in a `role="status"` region; page scroll is never captured. State which gesture mode is set in the docs.
- `state:loading`: `skeleton` plus a polite "Loading map" status; list and search remain usable. `state:error`: `alert` with reason and Retry; the list stays. `state:static-fallback`: static image with `alt`, "Open in Maps" link, the list, the attribution.
- `variant:with-attribution`: attribution text and links bottom-end on a `color.bg.surface` backing, never covered by controls or marker popups (popups reserve a bottom inset), shown at all zoom levels, with the provider logo where required.
- Provider notes: MapLibre/OSM (attribution `© OpenStreetMap contributors` plus tile source), Leaflet (`attributionControl: true`), Google (logo and "Map data" links must stay), Mapbox (wordmark and `© Mapbox © OpenStreetMap` with the "Improve this map" link). Say in the docs what is not guaranteed in the canvas (section 1).
- Reduced motion: no fly or ease animations. RTL: control corners mirror; canvas does not. Failure: tile errors show a visible "Some map tiles didn't load" status without losing markers.

### map-marker
- Markup: `<button type="button" aria-pressed="false" aria-label="Berlin Mitte, open now">`; the accessible name is place plus status ("Berlin Mitte, open now", "Hamburg, visited", "Munich, closed"). Visible text inside the button (a letter, number or label) must be contained in the name (WCAG 2.5.3): `variant:with-label` shows "Berlin Mitte" in the pin label and the name begins with it.
- Selection model: markers use `aria-pressed` consistently (a marker toggles selected; one at a time unless multi-select is declared), never `aria-current`, so the state is the same on markers and the list row (`map-list-sync`, where the selected row uses `aria-current="true"`). Only one convention is used per map and documented.
- `state:default`: circle in `color.map.pin.default` with `color.map.pin.fg` label. `state:selected`: larger, ring and check glyph, `color.map.pin.selected`, `aria-pressed="true"`, opens `map-popup`. `state:visited`: check-mark glyph plus "visited" in the name, `color.map.pin.visited`. `variant:with-label`: label beside the pin, truncated with the full name in the accessible name.
- Order: markers are DOM siblings in a sensible reading order (distance from the center, or the list order) so Tab moves through them in that order, capped (with clusters) at about 50 focusable markers; beyond that, the list alternative is the documented route and clusters are the stops ("Skip to list" link at the start). State which applies in the docs: this system uses the list as the full alternative and the DOM order for the visible markers.
- Keys: Enter and Space toggle; Esc closes the popup and returns focus to the marker. Target at least 44 px including a transparent hit area (WCAG 2.5.8); a pin's outline in `color.bg.surface` separates it from the tile.
- Reduced motion: no bounce or drop animation; selection is instant. RTL: label placement is logical. Failure: a marker with no coordinates is not rendered on the map but stays in the list with "Location unavailable".

### map-popup
- Markup: a non-modal `<div role="dialog" aria-labelledby="popup-title">` (or `[popover]`) anchored to the selected `map-marker`, with the place name as a heading, a Close `icon-button` named "Close" and the actions as real links and buttons. It is not `role="tooltip"` and not a live region.
- `state:open`: opens on marker activation (click, Enter, Space), moves focus into the popup (the heading, `tabindex="-1"`, or the first action), traps nothing, and closes on Esc, the Close button or activating another marker; focus returns to the marker. `variant:card`: a richer place card (photo with `alt`, rating as text, hours, "Get directions" `button-secondary`, "View details" link).
- It follows the marker on pan and zoom and flips to stay inside the visible map without covering the attribution; on small screens it becomes a bottom sheet (a `modal` only if it covers most of the screen).
- Never opens on hover alone (WCAG 1.4.13 and touch/keyboard equivalence); an optional hover preview of the name is a tooltip only. Reduced motion: no scale-in animation. RTL: arrow and content mirror. Failure: missing photo shows a placeholder, missing hours say "Hours unavailable".

### map-controls
- Markup: a plain `<div role="group" aria-label="Map controls">` of `<button>`s, not a `toolbar` (a toolbar would need roving tabindex and arrow keys, which conflict with map pan keys). Each button is Tab-reachable in a fixed order.
- `variant:zoom`: "Zoom in" and "Zoom out" (disabled at limits with `disabled`), plus the four "Pan" buttons when the pan alternative is shown (always on touch-only and for users who turn on "Map movement buttons"). `variant:locate`: "Show my location" button, geolocation only on press, `state:locating` text ("Finding your location"), denied handled as in `location-picker`.
- `variant:layers`: "Map layers" disclosure `button` (`aria-expanded`, `aria-controls`) opening a `popover` of `radio` basemaps and `checkbox` overlays as native inputs; closes on Esc. `variant:fullscreen`: toggle with a stable name "Fullscreen" and `aria-pressed` (Fullscreen API, exit with Esc); focus stays on the button, the list and attribution remain reachable.
- Keyboard shortcuts (`+`/`-`) are the same as the canvas; buttons are 44 px (24 px minimum), spaced so the zoom pair is not mistaken for one control. Reduced motion: no animated zoom. RTL: group corner mirrors. Failure: if the Fullscreen API is unsupported the button is not rendered rather than disabled.

### marker-cluster
- Markup: `<button type="button" aria-label="12 stores near Kreuzberg, zoom in to expand">`; the visible count is inside the name (WCAG 2.5.3). The bubble uses `color.map.cluster.bg` with `color.map.cluster.fg` count text and a square-ish outline so it differs from a single pin by shape and text, not only color.
- `state:collapsed`: the cluster bubble with count. `state:expanded`: activating it zooms to the cluster bounds (or spiderfies at max zoom into individual `map-marker`s) and moves focus to the first revealed marker; an `aria-live` polite status says "Showing 12 stores". Esc collapses a spiderfied cluster and returns focus to the cluster.
- Clusters recalculate after the map move ends (debounced), keep their DOM identity while the count is unchanged so focus is not lost, and never reorder markers during keyboard focus. The list alternative holds every place regardless of clustering.
- Reduced motion: expand is an instant cut. RTL: count digits follow locale. Failure: if the cluster algorithm fails, show all markers up to a cap with a "Zoom in to see more" status.

## 3. Search and selection

### location-search
- Markup: composes `combobox` (ARIA APG `combobox` with `listbox` popup; options are plain text places, no interactive descendants) around `<input type="search">` with a visible label ("Search places") and a submit button; an optional "Use my location" is a separate `button`, not inside the listbox.
- `state:suggestions`: results listbox opens on typing (not on focus alone), `aria-expanded`, arrows move `aria-activedescendant`, Enter selects and recenters the map (and updates the list), Esc closes then clears. A polite status announces "5 suggestions" (debounced). `state:no-results`: "No places found for 'Xyz'" with tips and a link to enter an address manually (`address-entry`).
- Suggestion text includes the place, region and type (Berlin, Germany); matched text is emphasised with `<strong>`, not color. Queries to the geocoder are debounced (300 ms), cancelled when stale, and use the provider or a self-hosted geocoder (Nominatim usage policy forbids autocomplete on the public server; say so).
- Reduced motion: no animated panel. RTL: input and results follow `dir`. Failure: geocoder error shows an inline alert and keeps the typed text; offline falls back to the typed address.

### location-picker
- Markup: a `<form>` with a heading, `location-search`, the map with a draggable-free pin (the pin moves with arrow keys or by click), a "Use my location" `button-secondary`, a manual address group (`address-entry`) and a Confirm `button-primary`.
- `state:drop-pin`: click or Enter on the map sets the pin; arrow keys nudge it by a visible step (the pan alternative); the chosen address is reverse-geocoded and announced politely ("Pin set near Oranienstraße 12"). Dragging the pin is allowed but never required (WCAG 2.5.7).
- `state:locating`: pressed "Use my location" shows "Finding your location" with a spinner icon and Cancel; geolocation is never called before the press; a timeout (10 s) yields a plain error. `state:permission-denied`: an `alert` explains "Location access is blocked", names how to re-enable it ("Click the lock icon in the address bar, set Location to Allow, then try again"; per browser or OS steps in a disclosure), and keeps the search and the manual address form open and focused as the fallback; the app works fully without location.
- `state:selected`: pin plus a confirmed summary (address, coordinates as secondary text) with "Change" and Confirm; the result is also a form value (`name="lat"`, `name="lng"`, `name="address"`). Never auto-submit.
- Reduced motion: no pin drop animation. RTL: form mirrors. Failure: reverse geocoding failure shows "We couldn't find an address for this pin" while keeping coordinates and allowing a manual address.

### area-selector
- Markup: a `<fieldset>` "Search area" with the map overlay and a form alternative; drawing by drag is never the only path.
- `variant:radius`: a center (from the map or `location-search`) and a radius via `slider` (`input[type=range]`) with a linked number input and unit select ("5 km"); the circle shows with a dashed outline plus a text size label, and `aria-valuetext` reads "5 kilometers". Arrow keys change the radius by a step, Shift by a larger step.
- `variant:polygon`: points are added by click or Enter at the keyboard-moved cursor, listed as an ordered `ol` of vertices (each with Move and Remove buttons and numeric lat/lng), with "Close shape", "Undo last point" and "Clear". The area shape has a text summary ("4 points, about 12 km2"). Esc cancels the drawing; Enter on "Close shape" finishes.
- Selection is announced politely ("Radius 5 km around Berlin, 38 places"). Minimum and maximum areas are enforced with an error message. Reduced motion: no animated outline. RTL: panel mirrors. Failure: an invalid or self-intersecting polygon shows an inline error and keeps the points.

## 4. Results and routes

### map-list-sync
- Markup: the map and a `ul` of results (`li` with name, address, distance and status, each with a real "Select" `button` or the name as a button) sharing one array and one selection value.
- `variant:split`: list beside the map (list first in DOM order, 360 px wide); selecting a row selects its marker (`aria-pressed` on the marker, `aria-current="true"` on the row) and centers it; selecting a marker scrolls its row into view and focuses nothing unexpected. `variant:mobile-toggle`: a two-button "List / Map" segmented toggle (`button`s with `aria-pressed`, constant visible label), one visible at a time; switching keeps the selection and moves focus to the view's heading.
- `state:hover-sync`: hovering a row highlights its marker and hovering a marker highlights its row; the same highlight happens on keyboard focus (focus-sync), and the highlight has a non-color signal (ring and thicker border plus larger pin). Hover only highlights; it never changes selection or opens a popup.
- The list shows only places in view when "Search as I move the map" is on, with a status ("12 places in this area"); the order is stable. Reduced motion: scroll-into-view is instant. RTL: split sides swap. Failure: markers without coordinates remain list-only.

### directions-panel
- Markup: a `<form>` with Origin and Destination `location-search` fields, a swap button ("Swap origin and destination"), a Mode group, depart/arrive time options and the result as an ordered list `ol` of steps with a summary ("24 min, 12.4 km").
- `variant:modes`: Mode is a `role="radiogroup"` of native radios styled as buttons (Drive, Transit, Walk, Bike), each with text and an icon; the route summary per mode shows time and distance as text. `variant:steps`: the `ol` of turn-by-turn steps (instruction text, distance), each step a button that highlights the segment on the map; the current step has `aria-current="step"`; instructions never rely on the map or arrows alone.
- `state:no-route`: an `alert` "No route found between these places for walking" with suggestions (try another mode, move a point, check road closures) and the inputs kept. Route lines use `color.map.route` with a dash pattern by mode and a legend; alternates are numbered "Route 1, Route 2" with different dash styles.
- Keyboard: Enter on the form calculates; Up/Down arrows in the mode group; Esc clears suggestions. Reduced motion: no route-draw animation. RTL: step arrows mirror. Failure: provider rate limit or error shows an inline alert with Retry; units follow locale.

## 5. Pages

### store-locator
- Composition: `<main>` with an `h1`, `location-search` plus "Use my location" (button press only), filters (a plain group of `aria-pressed` buttons or checkboxes), a `map-list-sync` with `map-container`, `map-marker`s, `marker-cluster` and `map-popup`. Landmarks: one `main`; the list region is a labelled `section`.
- `variant:split`: results list left (about 360 px), map right; selecting a row opens the popup on the marker. `variant:mobile`: the list is primary with a "Map" toggle; a selected result opens a bottom-sheet card with "Get directions" (a link to `directions-page` or the native Maps app).
- `state:no-results`: `empty-state` "No stores within 25 km" with "Widen the search", "Clear filters" and a manual address option; the map shows the searched area, attribution intact.
- Keyboard and AT: skip links to map, list and filters; the list alternative is the complete route. Mobile: single column, 44 px targets, pan/zoom buttons and no scroll hijack.

### map-search-page
- Composition: `<main>` with a full-height `map-container`, `location-search`, a results `map-list-sync` (side panel or mobile bottom list) and filters in a `modal` on mobile.
- `variant:search-as-move`: results refresh after the map move ends; the "Search as I move the map" checkbox (default on only where the product chooses, always user-controllable) and a "Search this area" button when it is off; one polite status announces the count; focus and the list scroll position are preserved.
- `state:loading`: `skeleton` rows and a "Loading results" status; the previous results stay until new ones arrive (no flash of emptiness); stale responses are discarded. Failure: inline `alert` with Retry; the list alternative still works.
- Mobile: map-first with a draggable sheet whose handle is a `button` (Expand/Collapse results) so drag is never required.

### directions-page
- Composition: `<main>` with the `directions-panel` (left or top) and the `map-container` showing the route (`color.map.route`, mode dash styles), alternates and step highlighting; a printable text version of the steps.
- `variant:default`: origin and destination from the URL or `location-search`; summary, alternatives and steps; "Open in Maps" and "Share route" actions. `state:no-route` and error handling as in `directions-panel`.
- Mobile: summary card and steps in a bottom sheet with an Expand button; map above; the step list remains the primary accessible representation; live location use is optional and only after a button press.
