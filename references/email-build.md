# Email build — rendering templates from tokens (minimal approach)

Goal: `ds.py email build <dir>` turns `patterns/email-*.html` sources into client-safe HTML + plain text, with **no new dependencies** (stdlib only). MJML export is optional.

1. **Resolve tokens → literals.** Load the DS token JSON, resolve aliases, and flatten to an `email` profile: `{"color.bg.canvas": "#F5F6F8", "color.text": "#1A1C21", "font.size.body": "16px", …}` for `light` and `dark`. Convert any `oklch()/hsl()/rgb()` to 6-digit hex and `rem` → px (×16). Fail if a needed token has no literal value.
2. **Author with placeholders, not `var()`.** Sources use `string.Template` syntax: `style="color:$color_text;font-size:$font_size_body"` (dots → underscores). Components are small Python functions returning strings (`button(href, label, tokens)`, `columns(cells)`, `receipt(rows)`), so VML/MSO blocks are generated, never hand-copied.
3. **Substitute** with `Template(src).substitute(tokens)` — `substitute` (not `safe_substitute`) so a missing token is a build error.
4. **Dark mode block**: render the `<style>` media query from the `dark` profile (`@media (prefers-color-scheme: dark){ .bg-canvas{background:#111318!important} … }` plus `[data-ogsc]` twins). This is the one place `!important` is allowed (email-only; exempt the email dir from the CSS lint hook).
5. **Inline.** Head `<style>` keeps only media queries/dark/hover; base classes are inlined by a tiny stdlib inliner (`html.parser` walk, class → declaration map, append to existing `style`). Supports class selectors only by design — keeps it ~60 lines. *Uncertainty: a full CSS inliner (juice/premailer) handles specificity; we avoid needing it by authoring styles inline via placeholders.*
6. **Plain text.** Each template also defines a `text()` function from the same content model (headings uppercased, links as `Label: https://…`, receipt as aligned columns). Never derived by stripping HTML.
7. **Checks** (fail build): HTML size > 80KB (Gmail clips ~102KB); `var(`, `display:flex|grid`, `rem` present; `<img>` missing `alt`/`width`; layout `<table>` missing `role="presentation"`; missing `lang`/`dir`, `color-scheme` metas, preheader, `<title>`; any `href` that is `#` or empty; link text "click here".
8. **Outputs**: `dist/email/<name>.html`, `<name>.txt`, and a docs preview page that embeds the HTML via `<iframe srcdoc>` with light/dark/images-off toggles (images-off = strip `src`).

**MJML alternative** (when the team already uses MJML/an ESP that accepts it): emit `.mjml` instead of step 5 — `<mj-attributes>` populated from the resolved token profile, components mapped 1:1 (`mj-button`, `mj-column`, `mj-table`, `mj-image`), then `npx mjml` compiles to HTML. Pros: battle-tested Outlook output. Cons: Node dependency, less control over a11y attributes (check `role="presentation"` and `lang` in output). React Email / Maizzle are equivalent options for JS stacks; the token profile JSON is the shared contract.
