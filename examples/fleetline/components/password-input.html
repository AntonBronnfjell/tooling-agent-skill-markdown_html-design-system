Password input

Usage

Use a password input for sign-in and for setting a new password on the Fleetline workshop tablet or dispatch console. Use a one-time-code input for SMS or authenticator codes.

  • Always offer Show: mechanics type with gloves on shared tablets and need to check what they typed.
  • autocomplete="current-password" on sign-in, "new-password" when creating one, so password managers fill or generate correctly.
  • When creating a password, list the requirements up front and show strength as a bar and a word.
  • Never block paste — it is how password managers work.

Anatomy

  1. Container — .input.input--affixed.password (from text field)
  2. Input — input.input__control[type=password]
  3. Reveal toggle — button.password__toggle[aria-pressed], icon + "Show" / "Hide"
  4. Strength (optional) — meter.password__meter + .password__strength-text
  5. Requirements (optional) — ul.password__rules, items with data-met

Examples

Hover and focus-visible are frozen with .is-hover and .is-focus-visible, which share their rules with the real pseudo-classes.

<div class="input input--affixed password">
        <input class="input__control" id="password" type="password" autocomplete="current-password">
        <!-- ships hidden; js/password-input.js reveals it and switches type + aria-pressed + label -->
        <button type="button" class="password__toggle" aria-controls="password" aria-pressed="false" hidden>
          <svg class="icon" aria-hidden="true"><use href="#icon-eye"></use></svg><span data-label>Show</span><span class="sr-only"> password</span>
        </button>
      </div>

      <!-- Strength + requirements (new passwords) -->
      <input class="input__control" type="password" autocomplete="new-password" data-strength="pw-meter" data-rules="pw-rules">
      <div class="password__strength">
        <meter class="password__meter" id="pw-meter" min="0" max="4" low="2" high="3" optimum="4" value="0"></meter>
        <span class="password__strength-text" data-strength-text></span>
      </div>
      <ul class="password__rules" id="pw-rules">
        <li data-rule="length:12">…At least 12 characters</li>
        <li data-rule="digit">…A number</li>
      </ul>

Do and don't

Accessibility

Keyboard interaction
KeyBehavior
TabInput, then the Show button
Enter / Space on the toggleShows or hides the password; focus stays on the toggle
  • The toggle is a real button named "Show password" (visible "Show" + visually hidden " password") with aria-pressed, so screen readers announce "Show password, toggle button, pressed".
  • The password is hidden again on submit so it never lands in form history as plain text.
  • Strength is a native meter with text ("Good"); requirement changes are announced politely after a typing pause, as "2 of 3 requirements met".
  • Requirements use a check or an empty circle icon plus text — not color alone.
  • Without JavaScript the toggle stays hidden and the field is a plain password input.
